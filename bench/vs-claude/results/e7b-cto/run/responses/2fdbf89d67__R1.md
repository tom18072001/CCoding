## Tóm tắt
Nghiệm thu. Tôi đọc `src/alert.js` và đối chiếu từng điều khoản của đề bài, và hành vi đều khớp. `npm test` do CCoding tự chạy cho kết quả xanh (baseline 0 pass / 1 fail, sau thực thi 1 pass / 0 fail). Phần diff chỉ chạm `src/alert.js` và không thêm test mới cho các trường hợp biên. Tôi không chạy thêm lệnh nào, nên các trường hợp biên mới được xác nhận bằng đọc mã.

## Tiêu chí nghiệm thu
| Tiêu chí | Kết quả | Bằng chứng |
|---|---|---|
| `npm test` xanh | Đạt | Kết quả CCoding tự chạy: sau thực thi exit 0, pass 1, fail 0. Baseline là exit 1. |
| Chỉ tính 5xx (500–599), mỗi host độc lập | Đạt | `src/alert.js` lọc `status >= 500 && <= 599`. Trạng thái `state` là Map theo host. |
| Cửa sổ nửa mở `(ts - windowMs, ts]`, `count >= threshold`, `count` = số event trong cửa sổ | Đạt | Vòng `while (q[head] <= e.ts - windowMs) head++` loại biên dưới. `count = q.length - head`. |
| Cooldown: không alert khi `ts < last + cooldownMs`, event trong cooldown vẫn tính cho cửa sổ sau, mặc định `cooldownMs = windowMs` | Đạt | Điều kiện `e.ts >= s.last + cooldownMs`. Event luôn được push vào `q` trước khi kiểm tra. Mặc định lấy bằng `opts.cooldownMs ?? windowMs`. |
| Input không sắp xếp, `ts` bằng nhau xử lý theo thứ tự input, không mutate input | Đạt | `filter` rồi `map` tạo mảng mới, sắp xếp theo `ts` rồi chỉ số gốc `i`. Mảng `events` không bị sửa. |
| Đầu ra `{host, ts, count}` sắp theo `ts` rồi `host` tăng dần | Đạt | Dòng `alerts.sort` ở cuối hàm. |
| Có test cho các trường hợp biên (biên cửa sổ, cooldown, ts trùng) | Chưa kiểm được | Diff chỉ chạm `src/alert.js`. Đề bài không bắt buộc test mới và tôi không chạy kịch bản biên nào. |

## Rủi ro & việc còn mở
- Test hiển thị chỉ có 1 file (`test/basic.test.js`). Các trường hợp biên chỉ được xác nhận qua đọc mã, chưa có test tự động bảo vệ.
- Hàm không kiểm tra đầu vào bất thường, ví dụ `windowMs <= 0` hoặc `ts` không phải số. Đề bài không đòi hỏi việc này.
- Hàm sắp xếp toàn bộ event nên tốn O(n log n). Mức này đủ cho đề bài.

## Việc tiếp theo
- **Bổ sung test biên cho `detectBursts`** · Phạm vi: thêm test vào `test/` cho biên nửa mở, cooldown (đúng bằng `alert.ts + cooldownMs` thì được alert), ts trùng, input chưa sắp xếp, nhiều host, và input không bị mutate. · Phòng Phát triển (`@senior-swe`). · Xong khi `npm test` xanh. Đề xuất, giám đốc quyết định có giao hay không.
