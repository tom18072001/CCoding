## Tóm tắt

Chưa nghiệm thu. Mã nguồn có một lỗi so với đề bài: `src/alert.js` coi status 600 là 5xx, trong khi đề chỉ tính 500–599. Các phần còn lại (cửa sổ nửa mở, cooldown, sắp xếp, không mutate input) đúng khi đọc mã và khớp bằng chứng `npm test` 4/4 pass. Tôi không chạy lại `npm test`, chỉ đọc mã và các test.

## Tiêu chí nghiệm thu

| Tiêu chí | Kết quả | Bằng chứng |
|---|---|---|
| Chỉ tính sự kiện 5xx (500–599) | Không | `src/alert.js` dòng filter dùng `e.status <= 600`, nên status 600 bị tính nhầm. Không test nào phủ biên này. |
| Cửa sổ nửa mở `(ts - windowMs, ts]` | Đạt | Vòng `while (times[start] <= ts - windowMs) start++` loại đúng biên. Test "window is half-open" kiểm windowMs 4000 → `[]` và 4001 → 1 alert. |
| Ngưỡng `>= threshold` và `count` đúng | Đạt | `count >= threshold`. Test đầu cho `count: 5`, test cooldown cho `count: 8`. |
| Cooldown: im lặng khi `ts < alert.ts + cooldownMs`, sự kiện trong cooldown vẫn được đếm | Đạt | Điều kiện `ts >= lastAlert + cooldownMs`, `times` không bị xóa khi cooldown. Test r3 cho alert ở ts 4 và 54 (count 6). |
| Mỗi host độc lập; cùng `ts` xử lý theo thứ tự input | Đạt | `Map` trạng thái theo host. Sắp xếp ổn định theo `ts` rồi chỉ số `i`. Test "equal ts" pass. |
| Kết quả sắp theo `ts` rồi `host` tăng dần | Đạt | Comparator cuối hàm. Test cooldown kiểm thứ tự a, b ở ts 4. |
| Không mutate input; input không cần sắp xếp | Đạt | `filter`/`map`/`sort` trên bản sao. Test kiểm `deepEqual(ev, copy)` với input không sắp xếp. |
| `npm test` xanh | Đạt | Báo cáo: baseline exit 1, sau thực thi exit 0 (4 pass, 0 fail). |

- Lỗi biên status 600 ở trên. Cách sửa là đổi `<= 600` thành `<= 599`, kèm test với status 599 (tính) và 600 (không tính).
