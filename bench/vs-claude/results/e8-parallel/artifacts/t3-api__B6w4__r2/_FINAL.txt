## Hợp đồng API
- Mọi `/tasks…` và `/audit`: thiếu hoặc sai `X-User` → 401 `UNAUTHENTICATED`.
- Thứ tự kiểm tra: 401 → 400 query → 404 → 403 → 400 body.
- `GET /tasks`, `GET /tasks/export.csv`: mọi vai trò; member được truyền `forceTeam` là nhóm mình. Gọi `parseTaskQuery` rồi `applyTaskQuery` rồi `tasksToCsv` đúng chữ ký hợp đồng.
- `GET /tasks/:id`: member xem nhiệm vụ nhóm khác → 404.
- `POST /tasks`: admin; manager chỉ nhóm mình (team khác → 403); member → 403.
- `PATCH /tasks/:id`:
  - Admin sửa mọi trường.
  - Manager: nhiệm vụ nhóm khác → 403; `team` khác nhóm mình → 403.
  - Member: nhóm khác → 404; không giao cho mình → 403; có khóa khác `status` → 403.
- `DELETE /tasks/:id`: chỉ admin; manager và member → 403 (sau 404).
- `GET /audit[?taskId=]`: chỉ admin; tham số khác hoặc `taskId` trùng → 400 `INVALID_QUERY`; trả `{items}` theo `seq` giảm dần.
- Body JSON hỏng được hoãn lỗi để 403 chạy trước 400. Các kiểm tra 403 dựa trên `body.team` dùng `!==`, nên body sai kiểu không gây lỗi.

Hai điểm đặc tả chưa nói rõ, tôi tự chọn:
- Manager POST thiếu `team` → bỏ qua kiểm tra 403 và rơi vào 400 `VALIDATION`.
- Manager hoặc member DELETE nhiệm vụ không tồn tại → 404 trước 403.

## Luồng dữ liệu
Mảng task (dữ liệu giả trong test, nhãn internal) → `tasksToCsv` → chuỗi CSV. Chuỗi gồm BOM, dòng header, rồi mỗi task một dòng, tất cả kết thúc bằng `\r\n`.

Mỗi ô qua các bước sau, theo thứ tự:
1. `null` hoặc `undefined` thành ô trống.
2. Với giá trị kiểu chuỗi bắt đầu bằng `= + - @`, tab hoặc `\r`, thêm `'` ở đầu. Số giữ nguyên, kể cả số âm.
3. Nếu ô chứa `,`, `"`, `\r` hoặc `\n` thì bọc trong `"…"` và nhân đôi `"` bên trong.

Ví dụ `=1,2` thành `"'=1,2"`. Module chưa nối vào route, phần đó thuộc S1.

Không áp dụng. Module không lưu hay ghi log gì, test chỉ dùng dữ liệu giả. Việc thêm `'` chống chèn công thức là biện pháp bảo vệ ở phía file CSV.
